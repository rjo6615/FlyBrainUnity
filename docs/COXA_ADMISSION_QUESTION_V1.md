# Coxa admission question V1 — design

Designed 2026-11-02, after the relay intervention was merged (PR #312). This document is
design only: no code has been written, nothing has run, and nothing is admitted. Every rule
below is fixed before any new outcome is seen. The protocol, code and tests will be
hash-locked and committed before any arm runs.

## The question

D3 (`COXA_HYPOTHESIS_D3_RESULTS.md`) was `NOT_CONSISTENT` by its three-leg rule. Per leg,
though, the H1 binding produced a strong, sign-reversing resistance loop in two legs:

| Leg | H1 Δf | H1_FLIP Δf |
|---|---:|---:|
| LF | −0.173 | +0.145 |
| LH | −0.191 | +0.206 |

RF failed because its hair-plate → coxa MN pathway barely drives the MNs. This was
explained afterwards: RF has fewer synapses per hair-plate neuron, and its relay
interneurons stay silent. RH failed because its hair plates are nearly silent in the held
posture.

This raises two questions:

1. **Policy.** What may a coxa coordinate count as when it has passed a closed-loop
   falsification test but has no anatomical binding?
2. **Evidence.** Do LF and LH actually meet that bar? The per-leg reading of D3 was chosen
   after seeing D3, so it must be confirmed prospectively before it counts for anything.

## Part A — what the existing standard says (unchanged)

The 20 admitted coordinates are counted under the v3 admission standard. Under
`LF_PROXIMAL_ADMISSION_PREREQUISITES_V1.md` and the remaining-leg audit, a coxa coordinate
needs three things:

- an anatomical population-to-muscle binding from independent reference evidence;
- activation and sign semantics justified independently of motion outcomes;
- a bounded validation protocol.

That anatomical reference gate is blocked: 0/8 supported LF endpoint correspondences, and
the project is local-only, so no new reference data will be requested. **Under the existing
standard, no coxa coordinate can be admitted, and this design does not change that.** The
v3 table, its gate and the 20/42 count stay exactly as they are.

## Part A — proposed policy: a separate CONDITIONAL tier (your decision)

The proposal is a second, separately counted status for coordinates that have
**behavioural-consistency evidence but no anatomical binding.** It is never merged into the
admitted count.

| Status | Meaning | Counted as |
|---|---|---|
| `ADMITTED` | Existing v3 standard (unchanged) | 20/42 |
| `CONDITIONAL` | All four entry criteria below are met | separate "+k conditional" |
| `BLOCKED_BY_INPUT` | The binding cannot be tested because the leg's sensory → MN drive is too weak in the model | not counted |
| `UNTESTED` | No preregistered test addresses this coordinate | not counted |
| `NOT_SUPPORTED` | A preregistered test failed | not counted |

**CONDITIONAL entry criteria (all required):**

1. **C1 — the binding was fixed in advance.** It was generated by a rule set before any
   closed-loop outcome. H1 (D2, name-geometry |cos| rule) meets this. No sign, gain or pool
   choice may come from motion outcomes.
2. **C2 — a falsification test with a sign-reversal control.** The coordinate passed a
   preregistered closed-loop test in which the flipped binding reverses the effect.
3. **C3 — prospective confirmation.** The pass was reproduced by a separately preregistered
   test (Part B), with the coordinate's channel isolated from the other hypothesis channels
   and across seeds not used before.
4. **C4 — integrity.** Every integrity check of those tests passed.

**What CONDITIONAL allows:**

- the channel may be enabled only through the labelled hypothesis session path, never the
  v3 default;
- every result that uses it carries the label `COXA_CONDITIONAL_H1`;
- it may be revoked by any later preregistered failure, which is recorded.

**What CONDITIONAL does not mean:** it is not an admission, not anatomical validation, and
not evidence for balance or gait.

**Coordinates covered by Part B.** D3 measured only the fore-aft (+Coxa) component. So the
only candidates are the two fore-aft channels whose legs passed in D3:

- `joint_LFCoxa`
- `joint_LHCoxa`

The other H1 channels in those legs (`LFCoxa_yaw`, `LHCoxa_roll`, `LHCoxa_yaw`) were not
tested by the reflex measure and stay `UNTESTED`. Initial statuses for the rest:

| Coordinate | Initial status |
|---|---|
| `RFCoxa` | `BLOCKED_BY_INPUT` |
| `RHCoxa_roll` | `BLOCKED_BY_INPUT` |
| Middle-leg coxa (silent encoder) | `UNTESTED` |
| Remaining coxa coordinates | `UNTESTED` |

**At most +2 conditional coordinates can come out of this design.**

## Part B — prospective confirmation test

**Context (fixed).** Step C arm A_ON, unchanged: assisted posture, hair plates delivered,
the same schedule, encoder, window (520–2000 ms), 20,000 physics steps and 4,000 ticks. The
20 v3 channels are unchanged. One fresh process per arm, each run once.

**Candidate channels.** Exactly `joint_LFCoxa` and `joint_LHCoxa`, using the H1 and H1_FLIP
definitions loaded unchanged, by hash, from the D2 result
(`docs/evidence/coxa-hypothesis-v1/run/result.json`). They are installed through the
existing D3 hypothesis session path (`coxa_hypothesis_loop.create_hypothesis_session`). No
other coxa channel is present.

**Seeds.** CNS seeds 1, 2 and 3.

- Seed 1 is the existing seed. Its C0 must reproduce the saved Step C A_ON.
- Seeds 2 and 3 have never been run. They are applied by the input adapter replacing
  `brain.rng` with `numpy.random.default_rng(seed)` at attach, before the first neural
  transition, and recording the state. This affects only stochastic external events,
  because the brain otherwise starts in its deterministic reset state.
- No kernel code changes. If attach does not happen before the first neural transition,
  the build stops with `PROTOCOL_NOT_BUILDABLE`.

**Arms: 9 in total, about 45 minutes.**

| Arm (per seed s) | Coxa channels |
|---|---|
| `C0_s` | none |
| `CAND_s` | H1 `joint_LFCoxa`, `joint_LHCoxa` |
| `FLIP_s` | H1_FLIP `joint_LFCoxa`, `joint_LHCoxa` |

**Integrity (all required, else `INCONCLUSIVE_INTEGRITY` with no labels):**

- **I1 Completeness.** All nine arms are COMPLETE, with 20,001 samples and 4,000 ticks each.
- **I2 Common random numbers.** Within each seed, the per-tick `uniforms_sha256` and the
  schedule are identical across its three arms.
- **I3 Reproduction.** `C0_1` equals the saved Step C A_ON in fired, uniforms, hair
  deliveries and qpos.
- **I4 Channels.** The 20 v3 channel definitions are identical in every arm. Exactly the
  two candidate channels are present in CAND and FLIP arms. Their definitions equal the D2
  hashes. Every coxa contribution satisfies |c| ≤ 0.25 rad.
- **I5 Prefix identity.** Within each seed, CAND and FLIP equal C0 until their first
  nonzero coxa command.
- **I6 Seeds applied.** The tick-1 uniforms of seeds 2 and 3 differ from seed 1's and from
  each other's.

**Measure.** The D3 measure, unchanged: the window-mean change, relative to `C0_s`, in the
coxa forward component of the leg (Step B encoder geometry), with BAR = 0.02.

**Per-seed pass for a coordinate (leg L in seed s):**

- `C0_s` hair-plate rate of L is > 0 in the window, so the leg is firing; and
- CAND_s Δf(L) ≤ −0.02, so the coxa moves posteriorly; and
- FLIP_s Δf(L) ≥ +0.02, so the effect reverses.

A non-firing leg in a seed counts as a failed seed for that coordinate.

**Labels per coordinate (`joint_LFCoxa`, `joint_LHCoxa`):**

| Label | Rule | Status consequence (if Part A is approved) |
|---|---|---|
| `CONFIRMED` | passes in all 3 seeds | `CONDITIONAL` |
| `PARTIAL` | passes in 1–2 seeds | stays a hypothesis; no tier change |
| `NOT_CONFIRMED` | passes in 0 seeds | `NOT_SUPPORTED` |

**Flags (reported with the label, not instead of it):**

- **`BOUND_LIMITED`.** The channel's |c| is within 0.01 rad of the 0.25 rad decoder cap for
  more than 50 % of window ticks in any CAND or FLIP arm. The shift is then partly set by
  the decoder bound.
- **`ROLLOVER`.** Any arm has a body-tilt sample above 90°.

**Descriptive measures (not gated):**

- Δf in all other legs (cross-leg effects);
- coxa MN pool rates;
- hair-plate rates and deliveries (the 120 Hz saturation is noted);
- contribution time courses and saturation time;
- body tilt mean and peak;
- comparison with D3's all-channel H1 effect sizes for seed 1.

## Predictions (expectations, not criteria)

- **LF and LH both CONFIRMED.** In D3, both effects were about 8–10× the bar and reversed
  under the flip, in the same Step C context.
- **Risks:**
  - Isolation removes `LFCoxa_yaw` and the LH roll/yaw channels, which may have added to
    the shift.
  - New seeds change the stochastic sensory events, and LF's coxa MN drive may vary.
  - LH ran close to the 0.25 rad cap in D3 (max 0.245), so `BOUND_LIMITED` is plausible
    for LH.

## Limits (stated before running)

- **Consistency is partly expected.** Step C already shows hair plates excite posterior
  pools. A confirmation is consistency with one published reflex (CxHP8 resistance) in one
  assisted context, not validation of the binding.
- **The actuation is offset-on-servo.** A shift is a setpoint shift, not a muscle force.
- **CONDITIONAL is a project policy, not a scientific result.** It doesn't satisfy the
  anatomical prerequisites and must never be reported as admission.
- **The seeds change only stochastic sensory event timing.** The connectome, engine and
  initial state are identical.
- **RF and RH stay blocked by input.** Unblocking them would need changes to drive or
  weights, which are not allowed for producing motor activity.

## Build and run plan (on approval)

1. **Protocol.** Write `docs/evidence/coxa-admission-v1/protocol.json`. It includes the
   Part A tier definitions, the D2 result hash and the candidate channel definition hashes,
   the seeds, integrity, labels and flags.
2. **Code.** Write `malecns_backend/live/coxa_admission.py`, which reuses the D3 loop
   (`coxa_hypothesis_loop`) and the Step C Trial; adds a seed-setting Trial subclass, the
   arm runner and the evaluator.
3. **Tests.** Write `tests/test_coxa_admission.py`, covering:
   - the channel subset equals the D2 definitions;
   - the seed is applied before the first transition (tiny engine);
   - the per-seed pass and label rules, including the non-firing-seed rule;
   - the flags;
   - integrity faults.
4. **Smoke.** A 100-step plumbing smoke test (C0_2, CAND_2), discarded. Then commit and
   hash-lock.
5. **Run.** Each of the nine arms once, in fresh processes (about 45 min), then the
   evaluation once.
6. **Record.** Write the results document. Update a separate status table
   (`docs/COXA_COORDINATE_STATUS.md`) only if Part A was approved. Raw arms stay local.
